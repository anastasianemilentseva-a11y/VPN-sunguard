Свой VPN. Папка связана с GitHub-репозиторием VPN-sunguard.

## Сейчас
Эта папка связана с https://github.com/anastasianemilentseva-a11y/VPN-sunguard (git init + remote origin, ветка main). Вход в GitHub работает: Git Credential Manager запомнил вход, первый коммит отправлен (push прошёл). В `.gitignore` — файлы ключей (*.conf, *.pem, *.key, *.ovpn, .env), в git они не попадут. Подключение к GitHub готово. Разбор задачи «свой VPN»: в Загрузках Telegram нашлись `SunguardTrade.conf` (готовый клиентский конфиг WireGuard) и `SunguardTrade.pem` (SSH-ключ RSA, похоже — вход на сервер). Это секреты, в git не кладём. Код Telegram-бота написан (папка `bot/`, инструкция в `README.md`), проверки проходят, код отправлен на GitHub (ветка main), на сервер не поставлен. Порядок: первый раз — по одобрению хозяйки, потом человек сам берёт настройки до 3 устройств; `/users` — список и «Отключить». 2026-10-22 на сервер поставлен WireGuard: `wg0`, сеть 10.8.0.0/24 (сервер 10.8.0.1), порт UDP 51820, NAT через eth0, включается сам после перезагрузки. Закрытый ключ сервера — только в `/etc/wireguard/wg0.conf` на сервере. Порт UDP 51820 в Tencent открыт (со слов хозяйки). Код бота разложен в `/opt/vpn-bot` на сервере, библиотеки стоят, служба `vpn-bot` включена, но не запущена — нет `.env`. Токен от @BotFather готов. Хозяйка вписывает BOT_TOKEN и ADMIN_ID в локальный `.env` (в этой папке, в git не попадает); затем копирую его на сервер (`/opt/vpn-bot/.env`, права 600) без показа и запускаю `vpn-bot`.

Решено про бота:
- По кнопке бот сам создаёт новую настройку WireGuard на сервере и присылает файл .conf и QR-код.
- Просить может любой; бот пересылает запрос хозяйке, она жмёт «разрешить» или «отказать».
- Бот работает на том же сервере, где VPN.
- Одному человеку — до 3 настроек (3 устройства).

Сервер: Tencent Cloud Lighthouse, Франкфурт, Ubuntu, IP 43.131.34.202, имя Ubuntu-VZ7p, SSH-ключ в облаке lhkp-7js7iap9 (файл `SunguardTrade.pem` в Загрузках Telegram). Вход: пользователь `ubuntu`, работает, sudo без пароля. 2026-10-22 проверено: Ubuntu 24.04, сервер пустой — WireGuard, Amnezia и Docker не стоят. `SunguardTrade.conf` ведёт на другой сервер, не на этот.

Важно: 2026-10-22 SSH-ключ `SunguardTrade.pem` целиком попал в чат сессии. Когда бот заработает, ключ стоит заменить на новый (сделать новый, старый удалить с сервера).
