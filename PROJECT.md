Свой VPN. Папка связана с GitHub-репозиторием VPN-sunguard.

## Сейчас
Эта папка связана с https://github.com/anastasianemilentseva-a11y/VPN-sunguard (git init + remote origin, ветка main). Вход в GitHub работает: Git Credential Manager запомнил вход, первый коммит отправлен (push прошёл). В `.gitignore` — файлы ключей (*.conf, *.pem, *.key, *.ovpn, .env), в git они не попадут. Подключение к GitHub готово. Разбор задачи «свой VPN»: в Загрузках Telegram нашлись `SunguardTrade.conf` (готовый клиентский конфиг WireGuard) и `SunguardTrade.pem` (SSH-ключ RSA, похоже — вход на сервер). Это секреты, в git не кладём. Код Telegram-бота написан (папка `bot/`, инструкция в `README.md`), проверки проходят, сохранён в git только на этом компьютере — на GitHub не отправлен, на сервер не поставлен. Порядок: первый раз — по одобрению хозяйки, потом человек сам берёт настройки до 3 устройств; `/users` — список и «Отключить». Следующий шаг: по слову хозяйки — отправить на GitHub; потом зайти на сервер, проверить WireGuard (обычный или Amnezia), создать бота в @BotFather и поставить.

Решено про бота:
- По кнопке бот сам создаёт новую настройку WireGuard на сервере и присылает файл .conf и QR-код.
- Просить может любой; бот пересылает запрос хозяйке, она жмёт «разрешить» или «отказать».
- Бот работает на том же сервере, где VPN.
- Одному человеку — до 3 настроек (3 устройства).

Важно: 2026-10-22 SSH-ключ `SunguardTrade.pem` целиком попал в чат сессии. Когда бот заработает, ключ стоит заменить на новый (сделать новый, старый удалить с сервера).
